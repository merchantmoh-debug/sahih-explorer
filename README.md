# Sahih Explorer

Follow every hadith of the six canonical collections back through its
narrators. See where chains across collections meet, and read each
narrator's record: grade, generation, dates, teachers and students.

The site is for students of hadith, teachers and da'wah writers who need a
chain they can show, and developers who want isnad data in their own tools.
It is a study aid. Gradings shown are those published by the scholars named
with them. The notes on each chain are automatic observations from the data,
not rulings.

## What it does

- **A hadith page built around its chain.** The chain of narration is drawn
  from the Prophet ﷺ to the compiler. The page shows:
  - each narrator's reliability and generation;
  - the word by which each received the report (حدثنا, أخبرنا, عن …);
  - branches where a chain switches (ح);
  - dashed links where someone is missing.

  The Arabic text links every name in it to that narrator. Below the chain
  are notes on the chain, published gradings, and the same report in the
  other collections, with all their chains merged into one graph.
- **Narrator pages.** Each has the narrator's grade, generation and dates,
  teachers and students weighted by how many chains use each link, where
  they appear in chains, family, places on a map, and every hadith they
  narrate. Narrators with the same name are listed side by side.
- **Did A narrate from B?** This tool checks a teacher and a student. It
  shows the direct link and the chains that use it, the shortest paths
  between the two, and their generations and death years.
- **Browse and search** by collection, book, standard reference
  (`bukhari 1`, `muslim 1907a`), words of a hadith in Arabic or English, or
  a narrator's name.
- **Glossary** of narrator grades, the twelve generations, words of
  transmission and grading terms.
- **Open data.** A read-only JSON API at `/api/v1` covers everything on the
  site, and dataset downloads are attached to GitHub releases.
- **English, Arabic and Kurdish (Sorani)**, with right-to-left layouts, dark
  mode, share images for every hadith, and sitemaps in every language.

## Quick start

Requires Node.js 20.9 or later.

```bash
npm ci
npm run dev        # builds the data first (under a minute), then starts Next.js
```

Open <http://localhost:3000>. Other commands:

| Command | What it does |
| --- | --- |
| `npm run build` / `npm start` | Production build and server (the build runs `data:build` first) |
| `npm run lint` / `npm run typecheck` / `npm test` | ESLint, TypeScript, unit tests |
| `npm run data:build` | Build `data/build/` from `data/source/`; skipped when up to date |
| `npm run data:rebuild` | The same, ignoring the up-to-date check |
| `npm run data:export` | Write the downloadable dataset to `dist/dataset/` |
| `npm run data:fetch-hadith-api` | Re-match hadith to the Hadith API (network) |
| `npm run geo:basemap` | Regenerate the map outline |
| `node scripts/smoke.mjs [base-url]` | Check key pages and API routes of a running server |

## How it is put together

```
data/source/          committed source data (see DATA.md)
data/build/           generated by npm run data:build, not committed
scripts/data/         the data build: alignment, chain graphs, notes, grouping, checks
scripts/legacy/       the scripts that produced the original data, kept for provenance
lib/data/             server-side readers for data/build, search, path finding
lib/vocab/            grades, generations, words of transmission, places, tags (en/ar/ckb)
lib/graph/            chain layout and merging
app/[locale]/         pages (en, ar, ckb)
app/api/v1/           JSON API
components/           site shell, graphs, hadith and narrator views
messages/             interface text for each language
tests/                unit tests (node:test)
```

Pages are rendered on the server and cached. The data is read from gzipped
JSON shards in `data/build/`, so a page loads only what it shows. Nothing
large is shipped to the browser.

## Data

The narrator records and chains come from two open datasets published on
Kaggle. Standard reference numbers, published gradings and some English
translations come from the public-domain
[Hadith API](https://github.com/fawazahmed0/hadith-api), matched by Arabic
text. [DATA.md](DATA.md) covers:

- where each part comes from;
- what the build derives;
- the integrity checks every build must pass;
- how to correct a record;
- known limitations.

## Corrections and contributions

Every hadith and narrator page has a **Report an error** link that opens a
pre-filled issue. Pull requests that fix the data are welcome. Edit the
record in `data/source/`, run `npm run data:build`, and say where the
correction comes from. Before sending code, run `npm run lint`,
`npm run typecheck` and `npm test`. CI runs these, builds the site and
smoke-tests it.

## Deployment

The site deploys to Vercel as a standard Next.js app. The build step
generates the data, and `next.config.ts` includes `data/build/` in the
server bundle. Set `NEXT_PUBLIC_BASE_URL` to the public URL; it is used in
canonical links, sitemaps and share images. Any Node.js host can run
`npm run build && npm start`.
