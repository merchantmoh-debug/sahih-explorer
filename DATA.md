# Data

Where the data comes from, how the build turns it into what the site and API
serve, how to correct it, and what it cannot tell you.

Chain graphs, notes and groupings are derived by this project's build. They
are study aids, not gradings. Gradings shown on the site are those published
by the scholars named with them.

## Sources

Everything the build reads is in `data/source/`, which is committed.

| File | What it holds | Origin |
| --- | --- | --- |
| `narrators.json` | 24,335 narrator records: names, class and generation, reliability grade, birth and death, places, family, teachers and students (as narrator IDs) | [Hadith Narrators Dataset (+24K)](https://www.kaggle.com/datasets/fahd09/hadith-narrators), `all_rawis.csv`, published on Kaggle by fahd09 (2018) |
| `hadiths/{collection}.json` | 34,433 hadith records of the six collections: Arabic text, the dataset's English translation, book, and the chain as a list of narrator IDs | [Hadith Dataset](https://www.kaggle.com/datasets/fahd09/hadith-dataset), `all_hadiths_clean.csv`, by the same author, scraped from qaalarasulallah.com. Its `chain_indx` column refers to the narrator dataset's IDs |
| `external/hadith-api/{collection}.json` | For each hadith: the matching entry of the Hadith API, its standard reference number, the published gradings it carries, and English where the dataset has none | [Hadith API](https://github.com/fawazahmed0/hadith-api) by Fawaz Ahmed, released under The Unlicense (public domain). Generated by `npm run data:fetch-hadith-api` |

The map outline (`public/geo/basemap.svg`, `lib/geo/basemap.ts`) comes from
Natural Earth (public domain) through the `world-atlas` package, and is
regenerated with `npm run geo:basemap`.

The terms of the two Kaggle datasets are set on their Kaggle pages. If you
reuse the narrator or chain data, check those terms and credit the datasets
and qaalarasulallah.com alongside this project.

### How `data/source` was made

The site used to serve about 430 MB of JSON generated from the two CSV files
by the scripts now in `scripts/legacy/`: one file per narrator, each embedding
the text of every hadith that narrator appears in. `scripts/data/import-legacy.ts`
folded those files, once, into the compact source files above. That script
needs the legacy files, which are no longer in the repository, so it cannot
be run again. The files in `data/source/` are now the source of truth.

Two things were deliberately left behind in that import:

- **Translations attached by number.** Earlier scripts filled missing English
  by hadith number. Numbering differs between editions in several
  collections, so hundreds of hadith received the translation of a different
  hadith. Only the dataset's own English was imported. Missing English is now
  taken from the Hadith API only when the Arabic texts match closely (below).
- **Word-for-word "translations".** Some English had been produced by
  replacing Arabic words one by one. The build rejects text with those
  patterns (`GARBLED` in `scripts/data/lib/helpers.ts`), and a check fails the
  build if any remain.

### Matching to the Hadith API

`scripts/data/fetch-hadith-api.ts` downloads the Arabic and English editions
of each collection (cached in `.cache/hadith-api/`) and matches every hadith
**by its Arabic text, never by its number**: word bigrams of the normalized
text are compared with Jaccard similarity. A match is accepted at 0.8 or
above, or at 0.5 or above when the Hadith API number also falls between the
numbers of neighbouring strong matches. Each link records its similarity.
English is taken from the Hadith API only where the dataset has none and the
similarity is at least 0.8.

For Sahih Muslim the reference is the numbering of Muhammad Fuad Abd al-Baqi,
with letters for the sub-narrations (`1907a`), as used by most modern
editions and sites.

Published gradings present in the links, by grader: Zubair Ali Zai, al-Albani,
Shuaib al-Arnaut, Abu Ghuddah, Muhammad Muhyi al-Din Abd al-Hamid, Muhammad
Fuad Abd al-Baqi, Ahmad Muhammad Shakir and Bashar Awad Maarouf. There are
none for Sahih al-Bukhari and Sahih Muslim, whose contents the scholars of
hadith accept as authentic as whole collections.

## The build

```bash
npm run data:build     # data/source → data/build (skipped when up to date)
npm run data:rebuild   # the same, ignoring the up-to-date check
```

`npm run dev` and `npm run build` run it first. The output in `data/build/`
is not committed. It is up to date when neither the source files nor the code
that shapes the output (`scripts/data/`, `lib/vocab/`, `lib/text/`) have
changed since the last build. A full build takes under a minute.

`scripts/data/build.ts` does the following, in order.

1. **Narrators.** Names are split from honorifics (رضي الله عنه, ﷺ, رحمه الله …),
   which are shown separately. The Prophet ﷺ gets his own record (ID 1). The
   class and generation (Ibn Hajar's twelve *tabaqat*), the reliability grade
   (the terms of *Taqrib al-Tahdhib*), dates in AH and CE, and places are
   parsed. Places are matched to a small gazetteer (`lib/vocab/places.ts`)
   for the map.
2. **Chains read against the text.** The dataset lists each chain as
   narrator IDs but does not say how they appear in the text.
   `scripts/data/lib/align.ts` finds each listed narrator in the Arabic
   *isnad*. It uses a monotonic alignment that weights the parts of a name
   by how rare they are, and folds the article, so ليث and الليث match. It
   also reads:
   - the word of transmission before each name (حدثنا, أخبرنا, عن, أن, سمعت, قال …);
   - narrators cited together ("X and Y both said");
   - switches to another chain (ح, *tahwil*);
   - names in the text that the dataset does not identify;
   - where the chain stops short of the text.

   A chain is extended from the text only when exactly one of the last
   narrator's known teachers matches the name that follows, by a clear
   margin. Those narrators are marked as inferred.
3. **Chain graphs.** Each hadith's chain becomes a small directed graph
   (`scripts/data/lib/graph.ts`). It runs from the Prophet ﷺ, or from the
   last narrator when the report stops at a Companion or later, to the
   compiler. Chains that switch with ح become branches. Where the text names
   someone the dataset does not identify, the link is drawn as a gap. So is a
   report that reaches the Prophet ﷺ without a Companion.
4. **Chain notes.** `scripts/data/lib/notes.ts` records observations a
   student would check:
   - generations or death years out of order;
   - links no other chain or list attests;
   - unidentified narrators;
   - a name in the text that differs from the listed narrator's;
   - reports that stop at a Companion;
   - follow-up reports ("similar to it").

   The thresholds are at the top of that file. These are not gradings.
5. **References and gradings.** From the Hadith API links. A hadith's page URL
   uses its standard reference: `/en/bukhari/1`, `/en/muslim/1907a`. Records
   with no match use the dataset's own number with a `ds` prefix. Where two
   records share a number, the second gets a `-2` suffix.
6. **The same report across collections.** Two hadith are related when
   they share enough uncommon words: at least 60% of the shorter text's, with
   a Jaccard similarity of at least 0.3. Related hadith form groups, and a
   follow-up chain ("the same as it") joins the report before it. The
   hadith page draws the chains of a group merged, to show where they meet.
7. **Teachers and students.** The source lists are combined with the links
   the chains actually use, made symmetric, and counted: how many chains use
   each link, and whether the source lists it.
8. **Search, indexes and statistics** for the site and API.
9. **Integrity checks.** The build fails if any check is outside its limit.
   The results are stored in `meta.json.gz` and served at `/api/v1/meta`.

| Check | Limit | Last build |
| --- | --- | --- |
| Narrators | ≥ 24,000 | 24,335 |
| Hadith records | ≥ 34,000 | 34,433 |
| Duplicate hadith keys | 0 | 0 |
| Chain IDs with no narrator record | ≤ 600 | 94 |
| One-sided teacher/student links | 0 | 0 |
| Honorific text left inside names | 0 | 0 |
| Prophet ﷺ record correct | yes | yes |
| Garbled English translations | 0 | 0 |
| Hadith with published gradings | ≥ 18,000 | 18,935 |
| Hadith matched to a standard reference | ≥ 32,000 | 33,397 |
| Listed chain narrators found in the text | ≥ 80% | 99.3% |

Build files are gzipped JSON, read on the server by `lib/data/server.ts`:
`collections`, `meta` and `legacy` (old URLs mapped to new ones), narrator
shards (`narrators/{id % 64}`), hadith per collection and book
(`hadiths/{collection}/{book}`), search rows, and the edge list
(`graph/edges`). Types are in `lib/data/types.ts`.

## Downloads

```bash
npm run data:build && npm run data:export
```

This writes `dist/dataset/`:

- `narrators.jsonl` holds one narrator per line.
- `hadiths.jsonl` holds one hadith per line, with its chain graph and notes.
- `edges.csv` lists the teacher → student links, with chain counts.
- `meta.json` holds the counts and the integrity checks.

Pushing a tag named `data-v*` (for example `data-v2026.09.25`) runs the
*Dataset release* workflow. It builds, exports and attaches the files to a
GitHub release. The same data is available per record from the JSON API;
see the developer page on the site.

## Corrections

Every hadith and narrator page has a "Report an error" link. It opens a
pre-filled issue using the *Data correction* form.

To fix something yourself:

1. Find the record. Hadith are in `data/source/hadiths/{collection}.json`,
   one per line, by `legacy_id`. A hadith's JSON link shows it as
   `reference.sourceId`. Narrators are in `data/source/narrators.json`, one
   per line, by `id`.
2. Edit the line. Keep it valid JSON and keep the record on one line, so the
   diff stays readable.
3. Run `npm run data:build`. The integrity checks must pass.
4. Open a pull request that says where the correction comes from: book,
   edition and page, or a link.

Teacher and student lists are made symmetric by the build, so a link needs
adding on one side only.

## Limitations

- **Dates are sparse.** Death years are recorded for 3,954 of 24,335
  narrators, so date checks are often unavailable.
- **Gaps.** 9,641 hadith records have at least one link where the text names
  someone the dataset does not identify, or where a report reaches the
  Prophet ﷺ without a Companion.
- **Identity.** Narrators who share a name can be misidentified in the source
  data. Where the text points to someone else, the chain notes say so. The
  narrator page lists others with the same name.
- **English.** 604 hadith records have no English translation.
- **Coverage.** The dataset does not contain every hadith of every edition.
  For example, part of Sunan Ibn Majah is missing.
- **Matching.** A few records matched to the Hadith API at the lower
  threshold may carry the reference or gradings of a neighbouring
  sub-narration. The similarity is stored with each link.
- **Grouping.** Reports are grouped by wording. Different reports with
  formulaic wording can be grouped together, and one report told in very
  different words can be missed.
